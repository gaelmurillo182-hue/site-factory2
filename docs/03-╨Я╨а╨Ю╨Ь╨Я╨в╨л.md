# 03 · Библиотека промптов

Копируйте и подставляйте своё. Порядок в файле = порядок в работе.

---

## Про длину промпта

Короткий промпт → средний результат. Это не потому, что модель ленится, а
потому что при недостатке ограничений она выдаёт статистически среднее решение —
то самое, которое выглядит «как все нейросетевые сайты».

```
❌ Сделай сайт для компании, которая продаёт твёрдосплавный инструмент
```

```
✅ Сделай сайт для B2B-поставщика твёрдосплавного инструмента.
   Покупатель — снабженец завода, ищет конкретный типоразмер под чертёж.
   Главное действие — оставить заявку на расчёт.
   Обязательно: таблица номенклатуры с фильтром по марке и размеру.
   Тон: инженерная документация, не SaaS-лендинг.
   Запрещено: Inter, фиолетовые градиенты, стоковые фото людей в касках.
   Не выдумывай сертификаты и цифры — ставь [[НУЖНО ОТ КЛИЕНТА]].
```

Разница не в вежливости. Разница в количестве отсечённых плохих вариантов.

## 1. Старт нового сайта

### 1.1. Есть только текст о компании

```
/brief

Компания: <название>
Чем занимается: <в двух предложениях>
Продукция: <перечень групп>
Город: <город>
Клиенты: <кто покупает>
Сайта нет / сайт: <url>

Задай мне вопросы блоками по 5, чтобы собрать полный бриф.
Всё, чего не знаешь, помечай [[НУЖНО ОТ КЛИЕНТА]] — не додумывай.
```

### 1.2. Есть сайт клиента

```
/brief https://example.ru

Зайди на сайт, разбери что за компания, что продаёт, кому и чем отличается.
Отдельно: что на этом сайте работает и стоит сохранить.
Отдельно: список того, что ты НЕ смог понять с сайта — это вопросы клиенту.
```

### 1.3. Запуск полного цикла

```
/new-site brief/имя-клиента.md
```

## 2. Выбор направления

### 2.1. Три концепции

```
Прочитай brief/имя-клиента.md и предложи ТРИ принципиально разных
визуальных направления. Не три оттенка одной идеи — три разных подхода.

Для каждого:
— название в 2–3 слова
— почему это подходит именно этой компании (одно предложение)
— шрифтовая пара с открытой лицензией, конкретные названия
— палитра 5–6 цветов словами и hex
— что делает вёрстку узнаваемой
— одно смелое решение, которое ты можешь защитить

Только словами. Код не пиши. Я выберу одно.

Запрещено во всех трёх: Inter, Roboto, Montserrat, Poppins как основной шрифт;
градиент фиолетовый→синий; иконка в скруглённом квадратике над заголовком.
```

### 2.2. Если все три скучные

```
Все три — середина. Ни одно не выглядит так, будто его сделал человек с мнением.

Дай ещё три, но каждое должно нарушать одно общепринятое правило
корпоративного сайта и объяснять, почему это уместно именно здесь.

Ориентиры: швейцарская типографика, техпаспорт изделия,
каталог подшипников 1970-х, инженерный чертёж.
Антиориентир: любой SaaS-лендинг.
```

### 2.3. Взять стиль с референса

```
Используй скилл design-dna.

Референс: <url или приложи скриншот>

Извлеки: сетку, типографскую шкалу, палитру, плотность, характер движения.
Не копируй макет — извлеки принципы и объясни, какие из них применимы к
brief/имя-клиента.md, а какие нет и почему.
```

## 3. Токены и контент

### 3.1. Токены

```
Направление выбрано: <название>.

Создай sites/<slug>/src/styles/tokens.css:
— цвета в OKLCH с hex-фолбэками
— типографская шкала (не произвольные px)
— шаг сетки 8px и вся шкала отступов от него
— радиусы, тени, длительности анимаций

Проверь контраст каждой пары «текст / фон» — минимум 4.5:1, покажи цифры.
Дальше ни один компонент не имеет права использовать значение вне токенов.
```

### 3.2. Тексты

```
Напиши все тексты сайта в sites/<slug>/content.md.

Читатель — снабженец завода. Мало времени, три конкурирующих КП на столе.

Первый экран должен за 5 секунд ответить: что продаём, кому, почему у нас.
В каждой секции — конкретика: марки, размеры, сроки, наличие.
Кнопки — о результате («Получить расчёт»), не о действии («Отправить»).

Запрещено: «инновационный», «динамично развивающаяся», «команда
профессионалов», «индивидуальный подход», «широкий спектр», lorem ipsum,
любые выдуманные цифры, сертификаты, годы и отзывы.

Чего не знаешь — [[НУЖНО ОТ КЛИЕНТА: вопрос]].
В конце — список всех таких мест отдельным блоком.
```

## 4. Вёрстка

### 4.1. Посекционно

```
Свёрстай секцию Hero в sites/<slug>/src/sections/Hero.tsx.

Текст — из content.md, дословно. Все значения — из tokens.css.
Мобильный сначала (390px), потом брейкпоинты вверх.
Семантика: header/nav/main. Alt у изображений. Фокус видим.

Полный код без сокращений. Никаких «// остальное аналогично».
Сверстал — покажи и остановись. Дальше не иди.
```

### 4.2. Таблица номенклатуры

```
Свёрстай секцию каталога.

Данные: <приложи CSV или опиши колонки>

Требования:
— на 1920px таблица, на 390px карточки, не горизонтальный скролл
— поиск по названию и артикулу
— фильтр по марке сплава и по типоразмеру
— сортировка по любой числовой колонке
— выделение строки при наведении
— кнопка «запросить цену» на строке, пробрасывает артикул в форму

Данные держи в отдельном ts-файле, не в компоненте.
```

### 4.3. Форма заявки

```
Свёрстай форму заявки.

Поля: <перечислить>. Обязательные пометить.
Валидация на клиенте, сообщения об ошибках на русском, под полем.
Состояния: покой / отправка / успех / ошибка сети.
Каждое поле — с <label>, не с placeholder вместо лейбла.
Кнопка недоступна во время отправки.

Отправку пока замокай — реальный эндпоинт подключим позже.
```

## 5. Движение

```
Статика согласована. Добавь движение.

— только transform и opacity
— выход быстрее входа (250ms in / 150ms out)
— не стартовать со scale(0), максимум scale(0.96)
— @media (prefers-reduced-motion: reduce) обязательно
— если JS не загрузился, весь текст виден (никаких висящих opacity: 0)
— длительности из токенов

Скролл-хореография — GSAP ScrollTrigger. Микро-переходы — CSS.
Не тащи GSAP ради одного fade-in.

После — покажи, что именно анимировано и почему.
```

## 6. Проверка

### 6.1. Визуальный QA

```
/polish
```

или подробно:

```
Через Playwright открой сайт, сделай скриншоты на 390px и 1920px.

Проверь:
— горизонтальный скролл на 390px
— наложение и обрезка текста
— контраст ниже 4.5:1
— отступы не кратные 8px
— строки длиннее 75 символов
— ошибки в консоли
— видимость фокуса при табуляции

Выдай список: ЛОМАЮЩЕЕ / ЗАМЕТНОЕ / МЕЛОЧИ.
Каждый пункт — где, что, почему, файл и строка.
Без файла и строки пункт не принимается.
```

### 6.2. Проверка на «сделано нейросетью»

```
Посмотри на сайт глазами дизайнера, который ненавидит AI-вёрстку.

Найди все места, по которым видно, что это сделала модель:
шрифты по умолчанию, фиолетовые градиенты, ряды из четырёх карточек,
иконки в скруглённых квадратиках, карточки в карточках,
одинаковые веса шрифта, серый на цветном.

По каждому: файл, строка, чем заменить.
Не оправдывай — если сомневаешься, значит признак есть.
```

### 6.3. Честная оценка

```
Оцени этот сайт по десятибалльной как арт-директор,
который не знает, что его делал ты.

Отдельно: что здесь действительно хорошо.
Отдельно: три вещи, которые ты бы переделал первыми.
Не смягчай. Если это шестёрка — скажи «шесть».
```

## 7. Редизайн

### 7.1. Аудит

```
/redesign https://example.ru
```

### 7.2. Сохранить стиль, починить вёрстку

```
Используй скилл redesign-existing-projects.

Фирменный стиль клиента менять нельзя: логотип, цвета, шрифт остаются.
Чинить: сетку, отступы, иерархию, мобильную версию, контраст.

Сначала — аудит списком, что именно сломано, с файлами и строками.
Потом жди моего «ок» и правь.
```

### 7.3. Было / стало

```
Через Playwright сними скриншоты старой и новой версии
на 390px и 1920px, положи рядом.

Под каждой парой — одно предложение: что изменилось и зачем.
Если где-то стало хуже — скажи об этом прямо.
```

## 8. Приёмы, которые заметно повышают качество

### Дать глаза

Самый большой прирост качества — не промпт, а Playwright MCP. Без него модель
верстает вслепую и «уверенно» рапортует об успехе. С ним — сама видит косяк
и правит.

### Заставить остановиться

Модель по умолчанию пытается доделать всё за один заход. Это стабильно даёт
худший результат, чем пошаговая работа. В промпт добавляйте:

```
Сверстал одну секцию — остановись и покажи. Дальше не иди без моего ответа.
```

### Запретить конкретное, а не «плохое»

```
❌ Не делай шаблонно
✅ Запрещено: Inter, Roboto, Montserrat; градиент #6366f1→#8b5cf6;
   ряд из четырёх одинаковых карточек; иконка в скруглённом квадратике
```

### Не смешивать слои вкуса

`frontend-design`, `impeccable` и `design-taste-frontend` — три конкурирующие
системы правил. Активированные вместе, они дают компромисс, то есть середину.
Один за раз.

### Требовать список неизвестного

```
В конце каждого ответа — блок «Чего я не знаю»: что ты додумал,
где не хватило данных, какие решения принял за меня.
```

Это работает лучше любых просьб «не выдумывай»: модели проще
пометить пробел, чем удержаться от его заполнения.
