# Генерация изображений

Свод по двум скиллам — `imagegen-frontend-web` и `brandkit` — сведённый в рабочую
схему. Нужен, чтобы не сочинять промпт заново каждый раз.

---

## Правило, которое нарушалось

**Если инструмент генерации доступен — им пользуются.** Это прямое требование
раздела 4.8 скилла `design-taste-frontend`: сначала генерация, потом реальные
стоки, и только в последнюю очередь — честная заглушка со списком того, что нужно
от клиента.

Признак нарушения: на странице одна галерея с фото и десять секций текста на
однотонном фоне. Так было на AVANA до правок.

---

## Два разных сценария — не путать

### Сценарий А. Изображения как контент сайта
Фактуры, атмосфера, фоны секций. Идут прямо в `src/assets/`.
Схема — ниже, раздел «Схема промпта».

### Сценарий Б. Изображения как макет
Секционные комп-макеты, по одному горизонтальному кадру на секцию, с типографикой
и CTA внутри картинки. Нужны, когда сайт ещё не свёрстан: сначала рисуем макет,
потом верстаем по нему. Это workflow скилла `image-to-code-skill`.

Правило скилла жёсткое: **один кадр — одна секция**. Лендинг из 8 секций даёт
8 отдельных горизонтальных изображений, а не одну простыню.

---

## Граница честности

Она не про вкус, она про репутацию клиента.

| Можно генерировать | Нельзя генерировать |
|---|---|
| Фактуры: шёлк, камень, свет, тень | Работы мастеров |
| Абстрактные градиенты и блики | Интерьер салона или зала |
| Атмосферные фоны секций | Портреты сотрудников |
| Бренд-борды: лого, палитра, типографика | Отзывы с именами и лицами |
| Макеты-компы для последующей вёрстки | Сертификаты, награды, логотипы партнёров |

Причина простая: человек записывается, ориентируясь на увиденное, и приезжает по
конкретному адресу. Сгенерированная «работа мастера» — это обещание, которое
никто не сможет выполнить.

Для вымышленного бренда в портфолио ограничений нет — там генерируется всё.

## Схема промпта

Собирается из семи слотов. Порядок важен: модель сильнее слушает начало.

```
[1 РОЛЬ КАДРА] для [2 ТИП ПРОЕКТА].
[3 СОДЕРЖАНИЕ: материал, свет, движение].
[4 ПАЛИТРА: словами + роль каждого тона].
[5 КОМПОЗИЦИЯ: где пустое место под текст].
[6 ЗАПРЕТЫ].
[7 ТЕХНИКА: тип съёмки, оптика, зерно].
```

### Слот 1 — роль кадра
`Abstract tactile texture for a section background` ·
`Atmospheric band for a section divider` ·
`Editorial still life` ·
`Full-bleed hero background`

### Слот 2 — тип проекта
`premium beauty salon website` · `table tennis club website` ·
`industrial B2B supplier website`

### Слот 3 — содержание
Материал и свет, а не сюжет: `silk-satin folds`, `matte dark stone`,
`translucent amber liquid light`, `soft raking light from the right`,
`slow diagonal wash of light`, `soft caustic reflections`.

### Слот 4 — палитра
Не hex, а словами, иначе модель ставит цветовые плашки:
`deep near-black warm surface`, `warm tan and amber highlights`,
`low chroma, palette-locked`.

### Слот 5 — композиция
Главное для фонов: `generous dark negative space on the left for typography`,
`large calm areas suitable for overlaying text`.

### Слот 6 — запреты
Список обязателен, иначе лезут лица и надписи:
```
no text, no logos, no UI, no people, no faces, no hands, no eyes,
no products, no flowers, no recognizable objects
```

### Слот 7 — техника
`editorial studio photography, large format, shallow depth of field,
cinematic tonal gradient, fine film grain, quiet luxury, restrained`

## Свои ключи: Gemini и OpenAI

Кроме встроенного инструмента можно генерировать своим ключом. Дешевле и без
чужих лимитов.

### Настройка — один раз

```
copy .env.local.example .env.local
```

Открыть `.env.local` и вписать ключ в нужную строку:

| Вариант | Переменные | Где взять ключ |
|---|---|---|
| AgentPlatform и другие OpenAI-совместимые прокси | `OPENAI_API_KEY` + `OPENAI_BASE_URL` | app.agentplatform.ru/api-keys |
| Прямой OpenAI | `OPENAI_API_KEY` | platform.openai.com/api-keys |
| Прямой Gemini | `GEMINI_API_KEY` | aistudio.google.com/apikey |

Заполняется один блок — тот, которым пользуетесь.

### Про прокси-платформы

Сервисы вроде AgentPlatform дают OpenAI-совместимый API: формат запроса тот же,
меняется только базовый адрес. Поэтому отдельный провайдер в скрипте не нужен —
достаточно указать `OPENAI_BASE_URL` и работать через `--provider openai`.

**Идентификаторы моделей у прокси свои** и не совпадают с названиями на сайте.
Гадать не нужно, скрипт умеет спрашивать сам:

```
node scripts/generate-images.mjs --provider openai --list-models
```

Команда выведет полный список и отдельно выделит те, что похожи на генерацию
изображений. Нужный ID подставляется флагом `--model`.

Скрипт понимает оба формата ответа: и `b64_json`, и ссылку на файл — прокси
отдают по-разному.

**Ключ не передаётся аргументом командной строки.** Аргументы видны в списке
процессов и остаются в истории оболочки. Скрипт читает `.env.local`, который
лежит в `.gitignore` и в репозиторий не попадает.

### Запуск

```
node scripts/generate-images.mjs \
  --prompts sites/avana/image-prompts.json \
  --out sites/avana/src/assets/texture \
  --provider gemini
```

Флаги:

| Флаг | Что делает |
|---|---|
| `--provider` | `gemini` или `openai`, по умолчанию `gemini` |
| `--base-url` | адрес API, если не задан в `.env.local` |
| `--list-models` | показать доступные модели и выйти |
| `--model` | переопределить модель |
| `--only 1,3,5` | сгенерировать только эти кадры |
| `--dry-run` | показать план без вызовов API |
| `--jpeg` | просить у API сразу JPEG (поддерживают не все прокси) |
| `--no-optimize` | не пережимать |
| `--max-width` | ширина после пережатия, по умолчанию 1600 |
| `--quality` | качество JPEG, по умолчанию 0.82 |

Пережатие встроено: скрипт сам приводит кадр к нужной ширине и отдаёт JPEG.
Отдельно `optimize-image.mjs` гонять не нужно.

Начинать стоит с `--dry-run`, затем `--only 1` на одном кадре — проверить, что
ключ рабочий и промпт даёт нужный результат, и только потом запускать весь набор.

## Стоимость и порядок вызова

Одно изображение — **1 кредит**, `marketing_studio_image`, разрешение 1k.
`get_cost: true` считает цену, ничего не запуская.

1. Один кадр → `generate_image`
2. От двух до двенадцати разных кадров → `generate_image_batch`
3. Ожидание → `jobs_wait`, группами не больше 12
4. Скачать по `result_url`
5. **Обязательно пережать** — модель отдаёт PNG на 1,4 МБ

### Пережатие без новых зависимостей

Скрипт в `scripts/optimize-image.mjs`: грузит PNG в Playwright, перерисовывает на
canvas с ограничением ширины и отдаёт JPEG. На AVANA дало 1361 КБ → 56 КБ.

## Порядок работы

1. Определить сценарий: контент сайта или макет.
2. Проверить границу честности — что генерируем, что просим у клиента.
3. Собрать промпты по схеме, палитру взять из `tokens.css`.
4. `get_cost` на одном кадре, посчитать бюджет.
5. `generate_image_batch`, дождаться, скачать.
6. Пережать, разложить в `src/assets/`.
7. Прогнать визуальный QA.
