# Скан линии

Полный регламент — `betting/MASTER_PROMPT_V5.md`. Прочитай его перед первым
сканом в сессии. Здесь — операционная последовательность.

## Железные правила, которые нельзя обойти

1. **Не выдумывать.** Нет коэффициента — не подставлять. Нет состава — не
   угадывать. Нет xG — не «примерно». Отсутствие данных идёт в Data Quality
   и снижает её, а не заполняется догадкой.
2. **Квоты нет.** VALUE: 0 — нормальный итог. Никогда не добирать ставки до
   числа, которое попросил пользователь.
3. **Хоккей: основное время ≠ с учётом OT/SO.** Разница на равных командах
   доходит до 8 пп. Если из линии непонятно, какой это рынок — спросить.
4. **Решения принимает движок, а не проза.** Числа в отчёте должны быть
   выводом кода, а не написаны от руки.

## Последовательность

### 1. Распарсить линию

Сохрани присланный текст в `betting/scans/<ДАТА>/line.txt`, затем:

```bash
cd betting/engine && python3 -m sbr parse ../scans/<ДАТА>/line.txt
```

Всё, что попало в `unparsed`, **переспроси у пользователя**. Не угадывай.

### 2. Статус матчей

Не начался / идёт / завершён. LIVE считается по другим правилам (раздел 5
мастер-промпта), prematch-данные становятся только baseline.

### 3. Собрать данные установленными скиллами

Футбол — `football-data`. NHL — `nhl-data`. НБА — `nba-data`. Теннис —
`tennis-data`. MLB — `mlb-data`. NFL — `nfl-data`. Новости и травмы —
`sports-news`. Рыночные ориентиры — `polymarket`, `kalshi`, `markets`.

**КХЛ этими скиллами не покрывается** — только официальные источники лиги и
клубов, вручную.

Сначала быстрый screening всей линии, потом глубокое исследование только
перспективных кандидатов. Не тратить одинаковое усилие на очевидно плохие рынки.

### 4. Собрать вход движка

`betting/scans/<ДАТА>/input.json`. Структура — в `betting/docs/WORKFLOW.md`,
рабочий пример — `betting/scans/_demo/input.json`.

Честно заполнить `data_quality`: каждый компонент — это то, что ты
действительно нашёл, а не то, что хотелось бы иметь. `uncertainty` в блоке
`model` — ширина твоей неуверенности в λ; при тонких данных ставь 0.35–0.45,
и движок сам уменьшит ставку.

### 5. Прогнать и записать

```bash
cd betting/engine && python3 -m sbr scan ../scans/<ДАТА>/input.json \
  --out ../scans/<ДАТА>/report.md \
  --graded ../scans/<ДАТА>/graded.json \
  --journal --db ../journal/bets.db
```

### 6. Adversarial-проход

Перед тем как показать карточку, пройди по 10 вопросам раздела 11
мастер-промпта по каждому VALUE. Если ответа нет — понижай до WAIT.

### 7. Дописать то, что код не знает

В отчёт по каждому VALUE добавь: 3 ключевых фактора со ссылками на источники,
главный аргумент ПРОТИВ, условие NO BET IF. По каждому WAIT — измеримый
триггер, а не «если сыграют хорошо».

## Что показать пользователю

Готовый `report.md` плюс одной строкой: сколько событий просканировано, сколько
VALUE/WAIT/REJECTED, общий риск в рублях и процент банка. Если VALUE = 0 —
сказать это прямо и не извиняться: это работающий фильтр, а не неудача.
