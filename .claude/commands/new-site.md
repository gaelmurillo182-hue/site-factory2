Сделай сайт с нуля.

Бриф или сырая информация: $ARGUMENTS

## Пайплайн

Идёшь строго по шагам. После шагов 2 и 3 — **останавливаешься и ждёшь ответа человека**.
Не проскакивай их «чтобы быстрее».

### Шаг 1. Бриф
Если `$ARGUMENTS` — путь к готовому брифу, прочитай его.
Если это сырая информация — вызови `brief-analyst`, получи `brief/<slug>.md`.
Покажи список `[[НУЖНО ОТ КЛИЕНТА]]`.

### Шаг 2. Направления → СТОП
Вызови `art-director`. Получи **три разных** направления словами.
Выведи их человеку. **Жди выбора. Не пиши код.**

### Шаг 3. Токены и контент → СТОП
После выбора:
- `art-director` создаёт `sites/<slug>/src/styles/tokens.css`
- `copywriter` создаёт `sites/<slug>/content.md`

Покажи палитру, шрифтовую пару и заголовок первого экрана.
**Жди подтверждения.**

### Шаг 4. Каркас
Подними проект:
```bash
npm create vite@latest sites/<slug> -- --template react-ts
```
Настрой Tailwind v4, подключи токены, поставь шрифты.

### Шаг 5. Вёрстка
`frontend-builder` верстает **секция за секцией**. После каждой секции — короткий
отчёт человеку. Не вываливай весь сайт разом.

### Шаг 6. Движение
Только после согласования статики. `motion-engineer`.

### Шаг 7. Визуальный QA
`visual-qa` через Playwright: 390px и 1920px. Получи список дефектов, почини
всё из категории «ломающее» и «заметное». Прогони QA повторно.

### Шаг 8. Сдача
Выведи:
- Как запустить: `cd sites/<slug> && npm run dev`
- Как собрать: `npm run build` → `dist/`
- Полный список `[[НУЖНО ОТ КЛИЕНТА]]`
- Что осталось несделанным и почему

## Запреты на всём пайплайне

- Не выдумывать факты о компании
- Не использовать Inter / Roboto / Montserrat / Poppins как основной шрифт
- Не делать фиолетово-синие градиенты
- Не писать «готово» без пройденного QA
