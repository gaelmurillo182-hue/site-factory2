# Решения владельца

Здесь фиксируются решения, принятые владельцем поверх решений совета директоров.
Совет обязан их исполнять, а не переспорить. Каждое — с датой и с тем, что оно
отменяет: без этого через месяц никто не вспомнит, почему в документах написано так.

---

## Р-01 · 29.08.2026 · n8n: заморозка снята

**Решение владельца.** n8n используем свободно, интегрируем с любыми API.
Заморозка подписок S1/S2, поставленная по лицензионному вопросу, снимается.

**Что это отменяет.** Пункт из `reports/13-cto-opensource.md`: «схема "общий n8n
для всех клиентов + подписка" закрыта до письменного ответа `license@n8n.io`».

**Уточнение, которое остаётся в силе `[Ф]`.** Ограничение лицензии касалось
не интеграции, а мультиарендности: хостинг воркфлоу и учётных данных нескольких
клиентов на одном нашем инстансе. Сборка воркфлоу клиенту и связка с любыми API
лицензией разрешены всегда.

**Как работаем.** n8n разворачивается в контуре клиента — это остаётся техническим
решением по умолчанию: так проще с доступами, так данные не смешиваются между
клиентами, так клиент не теряет систему при расставании с нами. Подписки продаём.
Если появится потребность держать несколько клиентов на своём инстансе — запросить
письменное подтверждение у n8n до, а не после.

## Р-02 · 29.08.2026 · Зарубежные модели разрешены

**Решение владельца.** Claude, GPT и другие зарубежные модели используем в клиентских
проектах. Ограничение «только GigaChat и YandexGPT» снимается: запрета на использование
зарубежного ИИ в РФ нет.

**Что это отменяет.**

- Правило №1 из `01-РЕСЁРЧ.md` §2.1: «Персональные данные не уезжают в зарубежный API».
- Строку списка отказов в `02-РУБРИКАЦИЯ.md` §7 «Передача персональных данных
  в зарубежные API — не делаем даже по просьбе клиента».
- Сквозное ограничение в шапке `03-ПРОДУКТЫ.md`.
- Третью фразу продажи в `04-ПРОДАЖИ.md` §1 и третье отличие на сайте.
- Красный флаг квалификации «клиент настаивает на зарубежном API».

**Что приходит на замену.** Не отсутствие правила, а другое правило:

> **Модель выбирается под задачу — включая Claude и GPT. Класс данных определяется
> на этапе ТЗ, и для каждого класса записывается, куда он уходит.**
>
> Для персональных данных работает одно из трёх, выбор фиксируется в договоре:
> обезличивание до отправки · согласие субъекта на трансграничную передачу
> с уведомлением Роскомнадзора · отечественная модель.
> Клиент всегда знает, куда уходит каждый класс его данных.

**Почему формулировку пришлось менять, а не просто удалять.** На фразе «данные
не уходят за границу» стояла треть позиционирования и третье отличие на сайте.
Оставить её при использовании Claude и GPT — значит написать на сайте неправду
в компании, которая продаёт честность. Новая формулировка сильнее: запрет
не отличает нас ни от кого, а «мы говорим, куда уходит каждый класс данных»
отличает.

**Что остаётся фактом и не отменяется решением `[Ф]`:**

- Требование локализации первичного сбора персональных данных по ст. 18 152-ФЗ
  действует независимо от нашего решения. Оно закрывается обезличиванием, согласием
  или отечественной моделью — но само не исчезает.
- Россия не входит в список поддерживаемых стран OpenAI; доступ может привести
  к блокировке аккаунта. Это риск клиента и наш, его нужно называть вслух.
- Anthropic принимает оплату зарубежной картой с зарубежным биллинг-адресом.
- Оператор персональных данных — клиент, но исполнителем нарушения будем мы.

**Кому что делать.** Юристу — формулировка согласия на трансграничную передачу
и порядок уведомления РКН, в пакет документов. Техническому — колонка «класс данных →
модель» в шаблоне ТЗ. Маркетингу и креативному — переписать третье отличие.
