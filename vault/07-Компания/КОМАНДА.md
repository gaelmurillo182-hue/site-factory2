# Команда

Тринадцать ролей. Определения — в `.claude/agents/`. Они живут в проекте:
вызывать можно в любой сессии, контекст компании они читают сами
из `agency/КОНТЕКСТ.md`.

**Что уже сделано этой командой:**
одиннадцать отчётов в `reports/` · протокол совета `ПРОТОКОЛ-СОВЕТА-01.md`
(имя компании, цены, приоритеты) · задачи квартала `ЗАДАЧИ.md` ·
идентичность в `brand/` · сайт `sites/ai-agency-site/`.
Начинать чтение — со `СВОДКА-ДЛЯ-ВЛАДЕЛЬЦА.md`.

## Совет директоров

| Роль | Кого звать | За что отвечает | Когда звать |
|---|---|---|---|
| Генеральный директор | `ceo` | стратегия, приоритеты, разрешение споров | «куда идём», «что делаем первым» |
| Коммерческий директор | `commercial-director` | линейка, цены, юнит-экономика, маржа | «сколько это должно стоить», «сходится ли экономика» |
| Директор по продажам | `sales-director` | воронка, каналы, скрипты, возражения | «где брать клиентов», «что говорить», «почему не покупают» |
| Директор по маркетингу | `marketing-director` | позиционирование, спрос, контент, метрики | «как о нас узнают», «чем отличаемся» |
| Креативный директор | `creative-director` | идея, нейминг, тон, кампании | «придумай название», «подача скучная» |
| Бренд-директор | `brand-director` | логотип, палитра, типографика, фирстиль | «как мы выглядим» |
| Технический директор | `cto` | стек, архитектура, что реально умеем | «сможем ли», «на чём делать», «сколько по правде займёт» |
| Директор по доставке | `delivery-director` | процесс от ТЗ до приёмки, сроки, загрузка | «как сделаем», «успеем ли», «почему проект тонет» |
| Директор по продукту | `product-director` | продуктизация услуг, дорожная карта | «как перестать делать каждый проект с нуля» |
| Финансовый директор | `finance-director` | налоги ИП, себестоимость, кэшфлоу | «сколько остаётся», «какой налоговый режим» |
| Юрист и комплаенс | `legal-counsel` | 152-ФЗ, договоры, маркировка ИИ | перед публикацией, договором, продажей в чувствительной нише |
| Директор по людям | `people-director` | найм, роли, передача знаний | «кого нанять первым», «кто это будет делать» |
| **Совет директоров** | `board` | синтез, разрешение противоречий, протокол | когда решение задевает несколько зон |

## Производственная студия

Уже была в проекте, работает по `CLAUDE.md`. Делает **клиентские** проекты,
а не идентичность самого агентства.

`brief-analyst` · `art-director` · `copywriter` · `frontend-builder` ·
`motion-engineer` · `visual-qa`

**Не путать:** `art-director` — дизайн клиентских сайтов.
`brand-director` — идентичность нашего агентства.

## Как это работает на практике

Каждый директор перед работой читает `agency/КОНТЕКСТ.md`. Там ссылки на ресёрч,
линейку, продажи, приложение и контракт честности. Пересказывать им контекст
в каждом запросе не нужно.

Отчёты складываются в `agency/reports/`. Решения — в протоколах совета
`agency/ПРОТОКОЛ-СОВЕТА-NN.md`. Задачи — в `agency/ЗАДАЧИ.md`.

**Правило созыва совета.** Совет не собирается по любому поводу. Он нужен,
когда директора спорят или когда решение задевает больше двух зон
ответственности. Одиночный вопрос решает профильный директор.

**Контракт честности** обязателен для всех: факт о внешнем мире — только
с источником и датой; наши решения помечены как решения; выдуманных клиентов,
кейсов и цифр не бывает.
